## 项目名称

**moonbase —— 零依赖、跨后端的 MoonBit 底层基础设施库**

## 赛道

新项目赛道（开源库 / 生态包）

## 一句话

纯 MoonBit、零 FFI、零第三方依赖的块分配器与定容容器库，native / js / wasm-gc 三后端全测，为嵌入式、游戏、运行时等「GC 不友好」场景打地基。

## 定位与生态关系

1. **与 core 互补而非重叠**：moonbitlang/core 的动态 GC 容器（Queue/Deque/HashMap 等）已成熟，本项目不重复它们——只提供 core 不提供的保证：容量固定（满即拒绝、永不扩容）、分配路径零堆分配、回收时点确定。两侧取舍由同负载对照基准量化（`benchmarks/gc_compare.mbt`，三组对照，解读见 docs/benchmarks.md）。
2. **生态质量痛点**：语言演进快，第三方包失修率高。本库本体（mem/collections）不 `import` 任何包（连 core 都不依赖），仅使用内置类型与稳定语法，把演进失效风险降到最低；CI 每次提交在最新工具链上三后端验证。
3. **确定性内存选择缺失**：嵌入式/实时/热路径需要确定性内存管理，现有生态以 GC 容器为主，容量上限与回收时点不在调用方手里。

## 技术方案

- 内存来自 `FixedArray[Byte]` 缓冲区，分配器返回字节偏移句柄（`storage()` 直接下标读写载荷），分配路径零堆分配（句柄为纯 `Int` 偏移，分配/释放本身不创建任何对象）
- `Allocator` trait 统一接口；bump/slab/buddy 三种分配器；`Arena[T]` 类型化分配
- 契约化 API：`Option` = 资源耗尽，`abort` = 契约违反；全部公开 API 标注复杂度
- 质量：`moon check` 零警告、每模块确定性伪随机属性测试（不变量校验）、三后端测试矩阵、CI 零 FFI 门禁
- 验收：`docs/acceptance.md` 给出 7 项可复现验收场景（三后端 42 测试、静态质量、一键端到端演示、契约行为、零 FFI 审计、对照基准、CI 全流程）
